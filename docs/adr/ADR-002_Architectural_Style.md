# ADR-002: Вибір монолітної архітектури

## Статус
Accepted

## Контекст
Проєкт розробляється невеликою командою (3-4 особи) з терміном реалізації MVP у 4 місяці. Логіка системи (пошук, вибір місця, оплата) є взаємопов'язаною.

## Рішення
Використовувати монолітну архітектуру з чітким поділом на рівні (Presentation, Application, Domain, Infrastructure).

## Обґрунтування
1. Швидкість розробки: Відсутність витрат часу на налаштування мережевої взаємодії між сервісами.
2. Простота розгортання: Один артефакт для деплою, що спрощує запуск системи.
3. Транзакційність: Легше забезпечити узгодженість даних при бронюванні квитка в межах однієї БД.

## Альтернативи
- Мікросервіси: Відхилено через надмірну складність на етапі MVP та необхідність складного DevOps-налаштування.

## Наслідки
### Позитивні
- Швидкий запуск продукту.
- Просте тестування.
### Негативні
- Складніше масштабувати окремі частини (наприклад, лише модуль пошуку) у майбутньому.
